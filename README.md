# 服務案件 KPI Dashboard

網頁版：https://11047021-commits.github.io/service-kpi-dashboard/

我用 9 週、305 筆模擬的設備服務案件，在 Excel 練習 CS 團隊每週要做的事：清理團隊追蹤表、計算 KPI、找出延誤原因，並在新資料進來時正確更新。

## 資料

- 資料為程式產生的模擬資料，與任何公司的實際營運無關。
- 欄位依職缺描述與一般設備服務流程設計：案件編號、開案日、結案日、狀態、優先度、案件類型、客戶廠區、負責人、延誤原因。
- 前 8 週 300 筆，第 9 週再新增 5 筆，用來測試 dashboard 能不能跟著更新。

## 做了什麼

1. **資料清理**：原始資料保留不動，另外複製一份清理，每個修改都記錄在 `Cleaning_Log`。共找出 7 類、42 處問題（日期格式、延誤原因寫法、空白負責人、重複案件、優先度寫法、名字空格、結案日早於開案日）。
2. **KPI 計算**：總案件、未結案件、準時結案率、平均處理天數，依結案週分組。
3. **延誤原因與案齡**：延誤原因件數、未結案件案齡，以及已超過目標天數的案件。
4. **每週維護**：資料轉成 Excel 表格（`Cases_Tbl`），新增第 9 週資料後檢查公式與圖表是否正確更新，並修正更新時發現的兩個問題。

## 結果（加入第 9 週後）

| KPI | 數值 |
|---|---|
| 總案件 | 305 |
| 未結案件 | 43 |
| 準時結案率 | 81% |
| 平均處理天數 | 5.2 天 |

目標天數（P1 2 天、P2 5 天、P3 10 天）為練習設定的假設值。
